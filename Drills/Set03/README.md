# Case Splitting (`|x|`, `min`, `max` and Parity)
Whenever `linarith` or `ring` gets stuck on an expression containing `|x|`, `max a b`, `min a b`, or an "`either/or`" (`∨`) condition, it is because those functions are defined piecewise (using an `if-then-else` under the hood). Our immediate reflex is to split the proof into two linear branches.

> [!Note]
> - `pos` stands for `positive`. Mathematically: `0 < x`.
> - `nonneg` stands for `non-negative`. Mathmatically: `0 ≤ x`.
> - `neg` stands for `negative`. Mathematically: `x < 0`.
> - `nonpos` stands for `non-positive`. Mathematically: `x ≤ 0`.

<br/>

## Drill 3.1
### `(x : ℝ) (h₀: |x - 4| ≤ 3) : 1 ≤ x ∧ x ≤ 7`

- `rw [abs_le]` at `h₀` applies the mathematical rule for absolute values. The `abs_le` (absolute less than equal to) lemma states that `|a| ≤ b ↔ -b ≤ a ∧ a ≤ b`. Transforming from `|x - 4| ≤ 3` into two linear inequalities: `-3 ≤ x - 4 ∧ x - 4 ≤ 3`.
- `constructor` looks at the main goal `1 ≤ x ∧ x ≤ 7`. Because the goal is a logical AND `(∧)`, `constructor` splits it into two distinct subgoals that must be proven separately: Goal 1 is `1 ≤ x` and Goal 2 is `x ≤ 7`.
- The `<;>` combinator takes the tactic on its right (`linarith`) and applies it to all subgoals generated by the tactic on its left (`constructor`). So Lean runs `linarith` on Goal 1, and then `linarith` on Goal 2.
- For Goal 1 (`1 ≤ x`):
    - `linarith` works by refutation. It assumes the negation of the goal, turning the goal into `x < 1`, which rearranges internally to `x - 1 < 0`.
    - It looks at the first half of the hypothesis: `-3 ≤ x - 4`. This rearranges to `1 - x ≤ 0`.
    - linarith adds the negated goal `x - 1 < 0` and the rearranged hypothesis `1 - x ≤ 0`, yielding `0 < 0` (False). This contradiction closes the first goal.
- Same for Goal 2 as Goal 1.

## Drill 3.2
### `(x y : ℝ) (h₀: |x + 1| < 2 ∧ |y - 3| < 4) : x + y < 8`

- `rw [abs_lt, abs_lt] at h₀` applies the mathematical rule for absolute values with strict inequalities. The `abs_lt` (absolute less than) lemma states that `|a| < b ↔ -b < a ∧ a < b`.
- Applying it twice transforms the hypothesis `h₀` from `|x + 1| < 2 ∧ |y - 3| < 4` into a combined set of linear inequalities: `(-2 < x + 1 ∧ x + 1 < 2) ∧ (-4 < y - 3 ∧ y - 3 < 4)`.
- `linarith` targets the main goal `x + y < 8` and works by refutation. It assumes the negation of the goal, turning it into `x + y ≥ 8`, which rearranges internally to `8 - x - y ≤ 0`.
- It extracts the relevant upper bounds from the expanded hypothesis: `x + 1 < 2` (which rearranges to `x - 1 < 0`) and `y - 3 < 4` (which rearranges to `y - 7 < 0`).
- `linarith` adds these two hypothesis inequalities together: `(x - 1 < 0) + (y - 7 < 0)` yields `x + y - 8 < 0`.
- It then adds this derived result `x + y - 8 < 0` to the negated goal `8 - x - y ≤ 0`, yielding `0 < 0` (False). This contradiction closes the goal and completes the proof.

## Drill 3.3
### `(x : ℝ) (h₀: x ≤ -2 ∨ 5 ≤ x) : 0 < x → 5 ≤ x`

- `intro hx` targets the implication `0 < x → 5 ≤ x` in the goal. It assumes the premise `0 < x` is true, adding it to the context as a new hypothesis `hx`, and leaves `5 ≤ x` as the new goal to prove.
- `rcases h₀ with hn | hn` performs case analysis on the disjunction (OR) hypothesis `h₀: x ≤ -2 ∨ 5 ≤ x`. It splits the proof into two distinct subgoals: one where we assume `hn: x ≤ -2`, and another where we assume `hn: 5 ≤ x`.
- The `<;>` combinator applies the `linarith` tactic to both of the subgoals generated by `rcases`.

- For Goal 1 (Case `x ≤ -2`):

    - `linarith` works by refutation, but it immediately finds a contradiction in the hypotheses themselves.
    - It takes the new hypothesis `hx: 0 < x` (which rearranges to `-x < 0`) and the case hypothesis `hn: x ≤ -2` (which rearranges to `x + 2 ≤ 0`).
    - Adding these yields `2 < 0` (False). This contradiction means this case is impossible, closing the first goal.

- For Goal 2 (Case `5 ≤ x`):

    - The case hypothesis `hn: 5 ≤ x` is exactly the same as the target goal.
    - `linarith` negates the goal, turning it into `x < 5` (which rearranges to `x - 5 < 0`).
    - It adds this to the case hypothesis `5 ≤ x` (which rearranges to `5 - x ≤ 0`), yielding `0 < 0` (False). This contradiction closes the second goal, completing the proof.

## Drill 3.4
### `(x : ℝ) : x ≤ |x|`

- `rcases le_total 0 x with h | h` uses the mathematical axiom `le_total`, which states that for any real number `x`, either `0 ≤ x` or `x ≤ 0`. It splits the proof into two distinct cases (subgoals), assigning the name `h` to the hypothesis in each case.
- The `·` (dot) bullet points isolate the proof steps for each individual case one at a time.

- For Goal 1 (Case `h: 0 ≤ x`):
    - `rw [abs_of_nonneg h]` applies the lemma `abs_of_nonneg`, which states that if a number is non-negative, its absolute value is itself (`|x| = x`).
    - This rewrites the target goal from `x ≤ |x|` to `x ≤ x`. Lean automatically recognizes that any number is less than or equal to itself (reflexivity) and immediately closes this goal.

- For Goal 2 (Case `h: x ≤ 0`):
    - `rw [abs_of_nonpos h]` applies the lemma `abs_of_nonpos`, which states that if a number is non-positive, its absolute value is its negation (`|x| = -x`).
    - This rewrites the target goal from `x ≤ |x|` to `x ≤ -x`.
    - `linarith` targets this new goal by refutation. It assumes the negated goal `x > -x` (which rearranges to `2x > 0`, or `x > 0`).
    - It looks at the case hypothesis `h: x ≤ 0` (which implies `-x ≥ 0`).
    - `linarith` combines the negated goal `x > 0` and the hypothesis `x ≤ 0`, yielding a contradiction (`0 < 0`). This closes the second goal, completing the proof.

## Drill 3.5
### `(x : ℝ) : 3 ≤ |x - 3| + x`

- `rcases le_total 0 (x - 3) with h | h` applies the `le_total` axiom to the expression `x - 3`, stating that either `0 ≤ x - 3` or `x - 3 ≤ 0`. It splits the proof into two distinct cases (subgoals), assigning the name `h` to the hypothesis in each case.
- The `·` (dot) bullet points isolate the proof steps for each individual case.

- For Goal 1 (Case `h: 0 ≤ x - 3`):
    - `rw [abs_of_nonneg h]` uses the fact that `x - 3` is non-negative to replace the absolute value `|x - 3|` with itself (`x - 3`).
    - This rewrites the target goal from `3 ≤ |x - 3| + x` to `3 ≤ (x - 3) + x`.
    - `linarith` targets this new goal by refutation. It negates the goal, turning it into `3 > 2x - 3` (which rearranges to `x < 3`).
    - It combines this negated goal with the case hypothesis `h: 0 ≤ x - 3` (which means `x ≥ 3`), yielding a contradiction and closing the first goal.

- For Goal 2 (Case `h: x - 3 ≤ 0`):
    - `rw [abs_of_nonpos h]` uses the fact that `x - 3` is non-positive to replace the absolute value `|x - 3|` with its negation (`-(x - 3)`).
    - This rewrites the target goal from `3 ≤ |x - 3| + x` to `3 ≤ -(x - 3) + x`.
    - `linarith` simplifies the algebraic expression on the right side. Since `-(x - 3) + x` expands to `-x + 3 + x`, the `x` variables cancel out, leaving just `3`.
    - The goal effectively becomes `3 ≤ 3`, which is trivially true. `linarith` derives the contradiction `3 < 3` into `0 < 0` when negating it and closes the second goal, completing the proof.

## Drill 3.6
### `(x : ℝ) : 2 ≤ |2 * x - 1| + |2 * x + 1|`

- `le_total 0 (2 * x - 1)` asserts the disjunction `0 ≤ A ∨ A ≤ 0` where for simplicity we do `A = (2 * x - 1)`.
- The first `rcases` divides the proof based on the sign of `2x - 1`.
- The `<;>` (chaining combinator) executes the second `rcases` across all active subgoals. This generates a 4-case matrix covering every sign combination for `2x - 1` and `2x + 1` (call this `B`) i.e. (`A≥0`, `B≥0`), (`A≥0`, `B≤0`), (`A≤0`, `B≥0`), and (`A≤0`, `B≤0`).
- `rw` unpacks the absolute values. It matches each branch's specific sign hypotheses (`h`, `h₁`) against `abs_of_nonneg` or `abs_of_nonpos` to replace `|A|` with `A` or `-A`.
- With the non-linear absolute values removed, `linarith` takes the resulting standard linear inequalities and executes its `0 < 0` refutation search to close all four branches.

## Drill 3.7

### `(a b : ℝ) : max a b + min a b = a + b`

- `le_total a b` asserts the disjunction `a ≤ b ∨ b ≤ a`.
- `rcases` splits the proof into two logical branches based on this disjunction: Case 1 where `a ≤ b` (named `h`), and Case 2 where `b ≤ a` (also named `h`).
- Case 1 (`a ≤ b`): `rw` uses `max_eq_right` to replace `max a b` with `b`, and `min_eq_left` to replace `min a b` with `a`. The goal becomes `b + a = a + b`, which `ring` easily closes by commutative addition.
- Case 2 (`b ≤ a`): `rw` uses `max_eq_left` to replace `max a b` with `a`, and `min_eq_right` to replace `min a b` with `b`. The goal becomes exactly `a + b = a + b`. The `rw` tactic automatically applies reflexivity at the end to close identical sides.

>[!Note]
> For naming convention, the tactic used is `max_eq_right` because maximum value exists in right side of `(a b)` i.e `b`. Same applies for all.

<br/>

## Drill 3.8
### `(a b : ℝ) : max a b - min a b = |a - b|`

- `le_total a b` asserts the disjunction `a ≤ b ∨ b ≤ a`, and `rcases` splits the proof into two logical branches (both named `h`).
- Case 1 (`a ≤ b`): `rw` uses `max_eq_right` and `min_eq_left` to simplify the left side to `b - a`. To strip the absolute value on the right side, `abs_of_nonpos` requires proof that `a - b ≤ 0`. The inline `(show a - b ≤ 0 by linarith)` proves this prerequisite. The goal becomes `b - a = -(a - b)`, which `ring` evaluates and closes.
- Case 2 (`b ≤ a`): `rw` uses `max_eq_left` and `min_eq_right` to simplify the left side to `a - b`. For the absolute value, `abs_of_nonneg` requires proof that `0 ≤ a - b`, which is provided inline via `(show 0 ≤ a - b by linarith)`. The goal evaluates to exactly `a - b = a - b`, which the `rw` tactic automatically closes via reflexivity.

## Drill 3.9
### `(x : ℝ) (h₀: x ^ 2 - 5 * x + 6 = 0) : x = 2 ∨ x = 3`

- `have h_fac: (x - 2) * (x - 3) = 0` manually introduces the factored form of the quadratic polynomial as a new hypothesis. The `linarith` tactic verifies it by matching its expansion to `h₀`.
- `mul_eq_zero.mp` applies the Zero Product Property (if `a * b = 0`, then `a = 0 ∨ b = 0`). `rcases` splits the proof into two logical branches based on this disjunction: `x - 2 = 0` and `x - 3 = 0` (both named `h`).
- Case 1 (`x - 2 = 0`): The goal is `x = 2 ∨ x = 3`. The `left` tactic discards the right side and tells Lean to solely prove the left side (`x = 2`). `linarith` immediately closes it using `x - 2 = 0`.
- Case 2 (`x - 3 = 0`): The `right` tactic discards the left side and targets the right side of the goal (`x = 3`). `linarith` immediately closes it using `x - 3 = 0`.

## Drill 3.10
### `(n : ℤ) : 2 ∣ (n + n ^ 2)`

- `Int.even_or_odd n` asserts the structural disjunction that every integer is either even or odd.
- `rcases` splits the proof based on this disjunction while simultaneously unpacking the hidden existential definitions for both branches. It binds a witness `k` and an equation `hk` for each case (`n = 2 * k` for the even branch, `n = 2 * k + 1` for the odd branch).
- Case 1 (Even): The divisibility goal `2 ∣ (n + n ^ 2)` unfolds into an existential search. `use 2 * k ^ 2 + k` provides the required witness. `rw [hk]` substitutes `n` with `k + k`, and `ring` automatically expands and verifies the algebraic equality.
- Case 2 (Odd): `use (2 * k + 1) * (k + 1)` provides the exact witness needed for the odd branch. `rw [hk]` substitutes `n` with `2 * k + 1`, and `ring` crushes the resulting polynomial expansion to close the goal.
